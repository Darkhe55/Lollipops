# 棒棒糖 Lollipops

一个基于 Web 的棒棒糖（Lollipops）逻辑谜题：放置「圆形头部 + 一格棍子」组成的 1×2 棒棒糖，
满足视线阻挡与互不相触规则。原生 SVG 渲染，内置规则推理回放、回溯求解器与自定义题板。

## 在线体验

```bash
npm install
npm start
```

`npm start` 会等开发服务就绪后用默认浏览器打开 **http://127.0.0.1:5220/**。

> 也可以 `npm run dev`（不会自动打开浏览器）。端口唯一来源是 `package.json` 的
> `puzzle.port`（本项目为 **5220**），`vite.config.ts`、`scripts/dev.mjs`、`scripts/ui-check.mjs`、
> `scripts/verify-game.mjs` 都从那里读取。

## 游戏规则

规则按标准 / 常见 Lollipops 实现，来源：

- [Puzzle Lollipops 官方规则页](https://www.puzzle-lollipops.com/?size=11)（"A lollipop is a circle
  (the 'head') attached to a single straight line (the 'stick') in an adjacent cell…"）
- [Logic Masters 的 MasyuPop 条目](https://logic-masters.de/Raetselportal/Raetsel/zeigen.php?print=true&chlang=en&id=000OYF)
  （Lollipops 规则段落；本作统一使用白圆头）
- [Sporcle Lollipops 示例题](https://www.sporcle.com/games/sproutcm/lollipops-puzzle-37/results)（写法约定：`O` 圆头 / `I` 竖棍 / `-` 横棍）

具体规则：

1. **形状**：一个棒棒糖 = 1 个圆形头部 + 上下左右相邻 1 格的棍子，共占 1×2 两格。
   横向相邻的一对是「圆头 + 横棍」，纵向相邻的一对是「圆头 + 竖棍」；棍子朝向必须和配对方向一致。
2. **全部归位**：盘面上每一格圆头、每一格棍子都必须属于某个棒棒糖（不能有落单的符号）。
3. **互不相触**：不同棒棒糖的格子不能上下左右相邻；斜角相邻允许。
4. **视线阻挡**：同一行 / 同一列中，忽略空格后相邻的两个同类符号之间必须有不同符号阻挡。
   符号分三类 —— 圆头、横棍、竖棍。
   也就是说，一行里出现 `圆头 … 圆头` 而中间没有任何符号是不行的；必须至少隔着一个横棍或竖棍。
5. **题面片段**：题目给出部分符号（圆头 / 棍子，可能只是半个棒棒糖），要求补全整个布局。
   内置题都保证在「符号类型」层面有且只有一个解，并且逻辑可推完。

### 白圆头 / 红叉

- 本作只使用**白圆头**；旧题库/旧存档里的黑圆头（值 1）会在读取时自动归一成白圆头。
- 右键可以把空格或正面符号改成**红叉**，表示玩家确认这里不放符号；红叉不参与棒棒糖配对，也不会影响唯一解判定。
- 右键点红叉会清空回空格；右键拖动时，第一次转换锁定源类型：空/正面 → 红叉，或红叉 → 空。

| 操作 | 说明 |

| 右键点红叉 | 清空为空格（题面预填格不动） |
| 按住左键拖动 | 连续放置同一种符号 |
| 按住右键拖动 | 第一次转换锁定源类型：空格/正面→红叉，或红叉→空；沿路连续处理 |
| 中键拖动 | 平移缩放后的棋盘 |
| 滚轮 | 放大 / 缩小棋盘 |
| 方向键 | 移动键盘光标（绿色虚线框） |
| 空格 | 光标处循环切换符号 |
| 1 / 2 / 3 | 光标处直接放白圆头 / 横棍 / 竖棍 |
| Backspace / Delete | 清除光标处符号 |
| Z / Shift+Z / Y | 撤销 / 重做 |
| C / H / L / S / Esc | 检查 / 提示一格 / 逻辑解题（回放中再按=停止）/ 显示解 / 清空 |
| P / R / M | 暂停继续回放 / 随机抽题 / 音效开关 |
| 滚轮 / 中键拖拽 | 缩放 / 平移画布 |
| + / − / 0 | 放大 / 缩小 / 视图复位 |

## 校验与错误高亮

「检查」会实时校验并高亮：

- **红色虚线框**：确定违规的格子 —— 与多个符号相邻、圆头/棍子朝向不匹配、改动题面预填格、
  同类符号紧挨着（中间没有格子可供阻挡）；
- **橙色点线**：同一行/列里两个同类符号之间还有空格，提示这里需要不同符号阻挡（还能补救）；
- 状态栏同时给出「还有几个符号没有搭档」「几处朝向不匹配」等提示。

完成条件：题面给定的符号都没有被改动，并且第 1–4 条规则全部成立。因为内置题在符号类型层面
唯一，满足这些条件时盘面就等于标准解。自定义题板不强制唯一解，此时任何满足规则的盘面都会被判完成。

## 自定义题板

侧边栏「自定义」→ 设置宽高（**4×4 ~ 20×20**）→「生成网格」：

| 操作 | 说明 |
|------|------|
| 左键点格子 | 循环：空 → 白圆头 → 横棍 → 竖棍 → 空 |
| 键盘 1 / 2 / 3 | 直接放白圆头 / 横棍 / 竖棍 |
| 键盘 0 / Backspace / Delete | 清空当前格 |
| 方向键 / Enter | 移动编辑光标 |

- 「载入题板」：把当前题面加入题库并立刻开始玩（题库保存在项目内 `data/library.json`，刷新仍在）；
- 「保存到题库」：覆盖保存正在编辑的题；保存 / 载入时会用求解器检查题面，并在编辑器下方提示
  「符号类型层有唯一解 / 有多解 / 无解 / 检查超时」，方便判断能否当正式题；
- 「求解」：对当前自定义题跑回溯求解器；
- 「逻辑解题」：用规则推理 + 反证回放解题过程；
- 题库列表里自定义题带「编辑」「×」按钮：编辑可把题面读回编辑器，删除需要点两次确认。
- 题面只需放部分符号；玩家补齐剩下的棒棒糖。自定义题不强制唯一解。

## 功能

- **内置题库**：8 道题（入门 / 进阶 / 挑战），全部经 `npm run check` 深度审计：参考解合法、
  符号类型层唯一解、逻辑可推满；
- **逻辑解题回放**：规则传播（唯一搭档 / 相邻排除 / 视线阻挡）逐帧回放，卡住时用「反证」
  （试值 + 回溯求解判断是否可补全）给出必然结论，状态栏显示每步理由。推理从**当前盘面**开始：
  玩家已经放好的符号会作为已知值写入推理引擎，未知格保持 unknown，回放帧的 `from` 取当前值，
  已经放对的符号不会被覆盖；只有当前标记与规则矛盾时才退回「只看题面」重推并纠正；
- **提示一格 / 显示解**：提示优先补空位、再纠正类型；
- **撤销/重做**：连续拖拽按格记录，可逐格撤销；
- **进度保存**：自动保存盘面与键盘光标，刷新不丢失；题面被编辑过时自动丢弃过期进度；
- **实时校验**：违规高亮 + 视线提醒；
- **音效特效**：Web Audio 合成拨弦 / 水滴音与通用落子动画，无外部资源；
- **缩放/平移**：滚轮缩放、中键或空白拖拽平移。

## 算法说明

- **符号类型层**：内部推理把每格编码成「未知 / 空 / 圆头 / 横棍 / 竖棍」；
  红叉只作为玩家标记，推理时视为“已知空地”。
- **规则传播**（`engine.ts`）：
  1. *唯一搭档*：某个符号格只剩一个可配对的相邻格 → 直接配对，并把它的其它相邻格标空；
  2. *相邻排除*：与已配对棒棒糖相邻的格子必须留空；一个格子接触 2 个及以上符号必然留空；
     朝向不兼容的相邻格必须留空；
  3. *视线阻挡*：同一行/列里相邻（忽略空格）的两个同类符号直接判矛盾；
  4. *2×2 局部*：一个 2×2 最多两个符号；相邻两符号必须配对；对角两符号的另外两格必须为空；2×2 出现 3 个及以上符号直接矛盾；
  5. *方向约束*：圆头/横棍/竖棍没有任何可配对方向时判矛盾；
  6. *行/列视线 DP*：每格维护“空/圆头/横棍/竖棍”候选域，对整行整列做 DP，保证同类符号之间必须隔一个不同符号，取所有可行序列的交集；
  7. *配对可行性（Hall）*：未配对符号必须能分配到互不相同的候选搭档格；候选不足直接判矛盾。
- **回溯求解**（`solver.ts`）：在未知格中挑候选最少的格子，分支「留空 / 与相邻格配对（两种朝向角色）」，
  每个分支先传播再搜索；用于显示解、自定义题求解、唯一解计数与反证。
- **逻辑回放**（`logic.ts`）：传播到不动点后若仍有未知，就选最受约束的格子逐个试值 ——
  若只有一种取值还能补全，即为必然结论（规则 4「反证」）；唯一解题一定能被推满。
- **题库生成**（`generator.ts`）：随机贪心铺合法棒棒糖 → 圆头统一为白 → 从全线索出发随机删减，
  仅当删除后符号类型层仍唯一才保留；`npm run check` 会再独立复核唯一解、参考解与逻辑可推满。

## 已知限制

- 红叉只是玩家标记，不参与棒棒糖配对与唯一解判定。
- 自定义题板不强制唯一解；多解时「逻辑解题」只保证解出一个完整解（规则推不动的部分由回溯补完），
  状态栏会提示「回放完毕」而不是「逻辑推满」。
- 逻辑解题依赖「反证探测」（试值 + 完整求解），对内置题足够快（每题回放计划 < 5ms）；
  超大自定义题（例如 20×20 且线索很少）可能较慢或超时。
- 规则只覆盖标准 Lollipops；没有实现 Masyu、数回等混合玩法。
- 没有图片识别 / 文本导入题目功能（自定义题在网页里手画）。

## 图片识图导入

```bash
# 预览：识别网格与线索符号，不写入题库
npm run import-image -- month.png

# 识别并追加到题库
npm run import-image -- month.png --append --name "识图 · 40×40"

# 额外尝试求解 / 唯一性检查（大盘面很可能搜到超时，只警告）
npm run import-image -- month.png --verify --budget 300000
```

| 参数 | 说明 |
|------|------|
| `--name 名称` / `--id ID` / `--series 系列` | 题库条目信息 |
| `--append` | 写入 `src/game/puzzles-data.ts` |
| `--verify` | 额外求解 / 校验唯一解（超时只警告） |
| `--map 簇号=符号` | 人工修正识别簇：1/2=白圆头（兼容旧值） 3=横棍 4=竖棍 |
| `--budget N` | 求解节点上限 |
| `--dry` | 只识别并打印盘面，不求解、不写入 |

- 识别原理：深色像素投影找网格线 → 每格中心区域墨迹按「长宽比 + 填充率」区分空 / 圆头 / 横棍 / 竖棍 → 同形状再聚类，`--map` 可覆盖。
- 题图里的米色底、蓝色小点等属于截图 UI 痕迹，会被当作背景忽略。
- 40×40 这类月赛大盘面默认跳过求解；`--verify` 会尝试求解和唯一性检查，超时只给警告，参考解允许留空。
- `npm run gen` 会覆盖 `puzzles-data.ts` 中的导入内容。

## 题板尺寸与形状支持

- **题面模型**：每格符号（空/白圆头/横棍/竖棍；玩家红叉只存在于进度），`width × height` 独立。
- **内置题库**：8 题，包含非正方形 **6×5、7×6、8×6、9×7**。
- **自定义题板**：上限从 **20×20 提升到 40×40**（本次修改），宽高可不同；
  点击循环 空→白圆头→横棍→竖棍，键盘 1–3 直填、退格清空。
- **识图导入**：40×40 大图自动识别成功（`month.png`）；识别结果中的旧黑圆头会归一成白圆头。
- **异形棋盘**：不支持「棋盘外空格」；但「空格符号」本身合法（题面只给部分符号），所以稀疏盘面是正常玩法。
- **验证**：`npm run build`、`npm run check` 通过；内置非正方形题参考解/逻辑计划合法；
  自定义 5×6、7×5、9×6、4×4、40×4 / 4×40 极限尺寸的编解码、渲染比例、编辑回填、求解闭环实测通过。
- **限制**：40×40 级题的回溯求解/唯一性会超时（`--verify` 只警告）；自定义题板保存不强制唯一性校验。
